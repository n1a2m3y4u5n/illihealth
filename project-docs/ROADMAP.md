# 빌드 로드맵

18개 기능을 4단계로 나누어 구축한다. 각 단계가 다음 단계의 토대이므로 **순서를 반드시 지킨다**. 같은 단계 내에서도 표의 순서가 의존성을 반영한다.

---

## Phase 0 · Foundation (인프라)

18개 기능 리스트에는 없지만 반드시 먼저 깔아야 하는 토대.

| 순서 | 작업 | 기능 # |
|---|---|---|
| 1 | 앱 셸 (Expo + RN + TypeScript) | — |
| 2 | 픽토그램 UI 프레임워크 | #14 |
| 3 | 인증 시스템 (픽토그램 PIN + SMS OTP + 생체) | — |
| 4 | Supabase 셋업 (Auth + DB + Storage + RLS) | — |
| 5 | OCR 엔진 통합 (Tesseract.js + Vision API) | — |
| 6 | 팀원 모듈 인터페이스 + Mock | — |
| 7 | TTS 음성 출력 | #15 |

**완료 시점**: 빈 앱이 열리고, 로그인되고, 픽토그램 UI 셸이 떠 있다. 기능 없음.

---

## Phase 1 · Core Loop (핵심 가치 루프)

사용자가 진단서 → 픽토그램 → 알람 → 기록 한 바퀴를 도는 핵심 사이클.

| 순서 | 작업 | 기능 # |
|---|---|---|
| 1 | 진단서 OCR 변환 | #1 |
| 2 | 개인 의료 보관함 | #3 |
| 3 | 복약 알람 | #4 |
| 4 | 복약·건강상태 일지 | #6 |

**완료 시점**: 첫 데모 가능. 중간 발표·예선 제출 가능.

---

## Phase 2 · Voice + Safety + Share (확장)

음성 1차 입력, 안전성, 공유 레이어를 얹는다.

| 순서 | 작업 | 기능 # |
|---|---|---|
| 1 | 음성 명령 입력 (STT) | #16 |
| 2 | 약/의료기기 설명서 OCR | #2 |
| 3 | 오프라인 모드 | #18 |
| 4 | 처방약 잔여량·리필 알림 | #5 |
| 5 | 약물 상호작용·부작용 경고 | #8 |
| 6 | 응급 상황 모드 | #9 |
| 7 | 의료진 QR 공유 | #13 |

**완료 시점**: 본선·결선 수준 데모.

---

## Phase 3 · Long-tail + Polish (완성)

특수 사용자층 + 마감 마무리.

| 순서 | 작업 | 기능 # |
|---|---|---|
| 1 | 만성질환 관리 모드 | #12 |
| 2 | 사진 기반 경과 기록 | #7 |
| 3 | 백신 접종 기록·알림 | #10 |
| 4 | 지역 감염병 경보 | #11 |
| 5 | 무자막 사용법 튜토리얼 | #17 |

**완료 시점**: 18개 전체 완성.

---

## 작업 순서 룰

| 룰 | 이유 |
|---|---|
| Phase 0 → 1 → 2 → 3 순서 엄수 | 각 Phase가 다음 Phase의 토대 |
| 같은 Phase 내에서 표의 순서를 따른다 | 순서가 의존성을 반영 |
| 튜토리얼(#17)은 절대 먼저 만들지 말 것 | 가르칠 화면이 없으면 의미 0 |
| Phase 1 끝나기 전까지 Phase 2·3 손대지 말 것 | 토대 없이 위 얹으면 다 무너짐 |
| 팀원 모듈은 Phase 0에서 인터페이스만 확정, 실제 구현은 병렬 | 클라이언트·백엔드 작업과 동시 진행 가능 |
